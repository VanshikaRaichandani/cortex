¹ every answer traces back to a page

Three steps, no magic in between.

¹

Upload

Drop in PDFs, Word docs, or plain text. Nothing is sent anywhere until you ask a question.

²

Index

Each file is split into overlapping passages and turned into embeddings, stored in a vector database scoped to your session only.

³

Ask

Your question is matched against the most relevant passages, and the model answers using only what it retrieved — with the source cited.

What's actually running under the hood

No proprietary black box — a fairly standard retrieval pipeline, kept plain enough to explain end to end.

Six stages, laid out the way a reference list would be — because that's essentially what retrieval is doing at query time.

¹
Text extraction — pypdf, python-docx
²
Chunking — overlapping word windows
³
Embeddings — local sentence-transformers model
⁴
Vector search — Chroma, per-session collection
⁵
Generation — Gemini 2.5 Flash, grounded on retrieved chunks
⁶
Interface — Streamlit

Where this breaks

It only knows what you uploaded — it won't answer general knowledge questions well, and it can still misread a passage or miss context split across chunks. Documents aren't stored after your session ends. It's a portfolio project, not a production tool.
